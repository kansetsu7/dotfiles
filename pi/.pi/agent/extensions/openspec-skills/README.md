# openspec-skills

Loads the six `openspec-*` skills only in the sessions that ask for them.

## Why

The skills are worth keeping and rarely worth loading. Left in a discovered
skill directory they cost ~350 tokens of system prompt in *every* session —
including the ones that will never run `openspec`. So they live in
`pi/.pi/agent/skills-optional/openspec/`, which no discovery path looks at, and
are contributed back through `resources_discover` when a session opts in.

```sh
/openspec on        # this session gets the openspec skills
/openspec           # what is this session doing?
```

## Why the flag is per session

The skills list is part of the system prompt, and the system prompt is the
first block pi marks with `cache_control`. Changing it invalidates the whole
cached prefix — negligible on turn 1, more expensive than the skills themselves
on turn 40.

A per-session flag means a resumed session rebuilds the *same* prompt it was
cached with, so `/resume` never pays for a re-cache. A per-process or per-project
flag would drift out of sync with whichever session you resumed into.

The flag is stored with `pi.appendEntry()`. Custom entries never enter LLM
context, survive `/resume` and `--fork`, and cannot be dropped by compaction, so
each session carries its own answer.

## Behaviour

| Situation | What happens |
|---|---|
| New session | Off, unless `PI_OPENSPEC=on` |
| `/openspec on` / `off` / `toggle` | Records the flag, then reloads |
| `/openspec` or `/openspec status` | Reports the current state, changes nothing |
| `/openspec off` when already off | No write, no reload — a reload would re-cache for nothing |
| Session > 10k tokens | Warns how much will be re-cached before reloading |
| `/resume` into an "on" session | Skills come back automatically, **no reload** |
| `/resume` into an "off" session | Skills stay away, **no reload** |
| `--fork` | Inherits the flag with the copied entries |
| Skills directory missing | Reports once, contributes nothing |

### Why resume needs no reload, and toggling does

Session replacement (`/resume`, `/fork`, `newSession`) builds a **fresh**
`ResourceLoader` (`core/agent-session-services.js:63`), so both directions
reconcile on their own. Within one runtime, `extendResources()` merges paths and
never prunes them (`core/resource-loader.js:243-256`) — only `reload()` resets
`lastSkillPaths` (`:333`). That is why a mid-session change of mind costs a
reload, and why it is the only reload this extension triggers.

`session_start` hands out an `ExtensionContext`, which has no `reload()`; only
command contexts do (`core/extensions/types.d.ts:254-290`). Nothing here needs
one, by the design above.

## Config (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `PI_OPENSPEC` | unset | `off` disables the extension; `on` defaults *new* sessions to on (a session that recorded a flag still wins) |
| `PI_OPENSPEC_COMMAND` | `openspec` | Command name, if it collides with something else |
| `PI_OPENSPEC_SKILLS` | `../../skills-optional/openspec` | Where the skills live |

The default path is resolved from this file's **real** path — `~/.pi/agent/extensions`
is a stow symlink, and walking `../..` through the link would land in
`~/.pi/agent`, where the directory deliberately does not exist.

## Updating the skills

They were generated by `openspec` 1.12.0 into `~/.claude/skills/` and then moved
here, so `openspec update` no longer maintains them. To refresh, regenerate into
a scratch directory and copy the `openspec-*` folders over
`pi/.pi/agent/skills-optional/openspec/`. Watch for `openspec init`/`update`
recreating them under `~/.claude/skills/` — if that happens they are loaded
unconditionally again, and in Claude Code too.

## Related

The companion change is in `pi/.pi/agent/settings.json`, which blocklists the
Claude Code skills pi should never see:

```json
"skills": ["~/.claude/skills", "!../../.claude/skills/synced/**"]
```

The pattern is relative to `~/.pi/agent` (where global settings paths resolve
from) and spells `.claude` out literally on purpose: pi calls minimatch without
`{dot:true}`, so `**/synced/**` silently matches nothing — `**` will not cross
the `.claude` segment. Before pi 1.2.0, `~` was not expanded in pattern
entries either (fixed upstream in #10765).

## Install

Nothing to do — `~/.pi/agent/extensions` is stowed from
`pi/.pi/agent/extensions`, and `*/index.ts` there is auto-discovered.
